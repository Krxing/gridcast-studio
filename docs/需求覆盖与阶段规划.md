# 需求覆盖与后续阶段规划

依据：导师口头四模块要求 + 原始需求分析 DOCX。当前交付定位为可运行、可演示、可替换预测引擎的科研原型；不是生产电力调度系统。

| 编号 / 需求 | 本次原型 | 边界或后续 |
|---|---|---|
| F1 数据管理 | CSV 上传、校验、历史曲线、质量统计、增量版本、未引用数据删除 | 非 Excel；非实时设备连接器；不自动补造负荷 |
| F2 训练与模型 | 三类真实模型、时间切分、训练日志、指标、人工发布与回滚 | 无自动超参搜索、外部权重导入或分布式训练 |
| F3 在线推理 | 异步多步预测/最近窗口回测、80/90/95% 经验区间、实际值回流评估 | 2–168 步；窗口训练时确定；不选任意历史时点 |
| F4 可视化 | 历史/预测/实际/区间、敏感度、逐步区间宽度、STL 四图 | 无因果解释或 SHAP 声明 |
| F5 业务 KPI | 峰值、累计电量、负荷率、测试 MAE/RMSE/MAPE、实测覆盖率 | 不定义易误导的统一“准确率”；未来误差待标签回流 |
| F6 模型对比 | 相同数据版本、预测步长、测试窗内比较多项指标 | 不将跨窗口指标直接排名 |
| F7 时序分解 | 真实 STL 鲁棒分解 | 未实现 CEEMDAN；不作为未来泄漏特征 |
| F8 认证权限 | 首次管理员、用户创建、三角色、BCrypt、JWT Cookie | 数据工程师能力并入工程师角色；未做 SSO/MFA |
| F9 异步任务 | SQLite 队列 + 独立工作进程，日志、进度、重启恢复 | 单实例；仅可取消排队任务 |
| F10 演示数据 | 一键生成 90 天数据、训练、发布、预测，显式合成标记 | 合成数据不证明业务有效性 |
| F11 导出 | CSV 溯源字段、浏览器打印为 PDF | 非服务器生成排版 PDF |
| 本地 / 云端 | 单套配置、本地启动脚本、多阶段镜像、非 root、持久卷 | Docker 本机未验证；不是双端自动同步 |
| 实时更新 | JSON/CSV 追加接口、界面每 4 秒刷新、可自动滚动预测 | 数据到达触发；无 MQTT/Kafka/定时采集器 |
| 自适应学习 | 误差/均值偏移监测、阈值重训、候选同窗评估、人工发布 | 批量受控重训，不是逐记录在线梯度更新 |
| 混合模型 | PyTorch 选择性状态递推 + 稀疏上下文注意力 + 门控融合 | 非官方 Mamba；无已验证城市级 / 线性复杂度声明 |
| 高精度与不确定性 | 真实留出评估、独立校准、Dropout/集成离散度 | 需真实数据实测；不承诺固定精度或覆盖保证 |

## 与文档设计不同的工程决定

1. Vue 3 自定义组件替代 Element Plus，视觉采用绿色能源工作台；保留 ECharts。
2. 单 FastAPI 静态托管替代独立 Nginx 前端容器，外部 HTTPS 代理按部署环境配置。
3. 任务采用独立进程而非 API 内训练线程，减少长训练阻塞请求。
4. API 使用原生 JSON 与 HTTP 状态码，具体规范见运行实例的 OpenAPI。模型/数据详情合并接口，未逐条复刻文档路径。
5. 采用经验预测区间而非将 MC 标准差直接称为置信区间；仅在真实标签可用时输出预测误差。
6. 原型数据集/模型列表暂不做服务端分页，任务/预测分别限最近 50/100 条。大规模数据需进一步分页、缓存和压测。

## 建议后续阶段

### A. 用真实数据完成科研验证
明确预测对象、采样间隔、预测跨度、更新频率与数据授权。选择至少一个真实场景，确定季节朴素/LSTM/已有模型等对照，按相同时间窗测试精度、区间覆盖/宽度、推理延迟；用误差分析确定下一轮改进，而不是先承诺百分比。

### B. 适配导师正式模型
提供模型代码、权重、输入列/顺序、归一化参数、时间窗口、依赖版本及既有指标。保持当前系统的数据契约和可视化，将 `engine` 的训练/推理接口替换为通过复现实验的正式模型，必要时加入 GPU 和官方 Mamba。

### C. 接真实采集与生产运维
完成数据源连接、幂等补传、缺测治理、漂移与报警验收；进一步加入分页、缓存、队列隔离、备份恢复、安全审计、访问控制和生产数据库。云端单实例先试运行，再根据实际并发拆分扩展。

### D. 业务与合同验收
由导师或项目方确定真实场景、指标阈值和测试方案。两城市部署、论文、专利和经济效益需要单独证据与外部工作，不作为本原型的已完成项。
